Deploy KCC20 / OMA L1 Token

Create a covenant-backed holder-token family using the proven OMA L1 compact-controller deploy route.

testnet-10: available to all OMA users mainnet: OMA PRO / TDPRO required signing stays local in browser

This page is for the new KCC20 deploy flow only. It does not replace the existing KRC-20 Deploy page.

Definition of Terms
Token Name
Human-readable display name written into the OMA L1 token state envelope. Max 64 characters; spaces are allowed.
Token Symbol
Short ticker for wallet Holdings and Cov Tools display. Use 2–16 characters, A–Z and 0–9 only; no spaces.
Decimals
Display precision from 0–18. RAW amount = human amount × 10^decimals.
Max Supply (RAW)
The fixed positive issuance cap recorded in the controller state. Zero is not unlimited and is rejected. Burns reduce issued supply, not this cap.
Initial Issue (RAW)
Optional first holder output amount. When zero, deploy creates a controller only.
Controller Carrier
KAS carried by the controller P2SH output. Current deploy-page default is 1 KAS; the backend still verifies mass and standardness.
Holder Carrier
KAS carried by the initial holder output when initial issue is greater than zero. Current deploy-page default is 1 KAS; the backend still verifies mass and standardness.
Transfer Rules
Current proven rule is owner signature required. Additional covenant rule options remain blocked until separate proof.
Network guard

Waiting for wallet status.

License guard

Mainnet deploy requires OMA PRO / TDPRO.
