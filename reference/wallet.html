How to create a broadcast batch file

Create a plain text file ending in .json. The file must describe one asset, one source wallet, one network, and one or more destination rows. Before broadcasting, select the same asset in the wallet, select the matching active wallet, and unlock the matching keyfile.

  1. networkId must match the active wallet network, such as testnet-10.
  2. sourceWalletAddress must exactly match the active wallet address shown above.
  3. Use either assetName for ticker-based sends or ca for contract-address sends.
  4. amountRaw is raw base units, not display units. For an asset with 8 decimals, 100000000 means 1 token.
  5. fulfillmentBatchId and each fulfillmentExecutionNonce must be unique 64-character lowercase hex strings.
  6. Broadcast Maker stops on the first failed row and downloads a result file after execution.
{
  "version": 1,
  "kind": "transfer_list",
  "networkId": "testnet-10",
  "sourceWalletAddress": "kaspatest:replace_with_active_wallet_address",
  "assetName": "TDTST",
  "ca": "",
  "decimals": 8,
  "fulfillmentBatchId": "1111111111111111111111111111111111111111111111111111111111111111",
  "rows": [
    {
      "purchaseId": "ROW-001",
      "to": "kaspatest:replace_with_destination_address",
      "amountRaw": "100000000",
      "fulfillmentExecutionNonce": "2222222222222222222222222222222222222222222222222222222222222222"
    }
  ]
}

This broker-facing file is generated from prepared bridge fulfillment work. It is only shown to the configured bridge inventory wallet for the active network.

How to create a coupon subscriber CSV file

Create a CSV file with a header row. The CSV controls recipients and optional subscriber details only. The wallet controls the selected coupon token and amount. KAS is not supported for coupons.

  1. address is required and must be a valid KRC-20 receive address for the active network.
  2. label, email, subscriber_id, and notes are optional wallet-supported columns.
  3. You may add marketing columns such as first_name, last_name, company, phone, source, signup_date, consent_email, and consent_sms.
  4. Unknown columns are ignored by the wallet importer and remain only in your source CSV records.
  5. Duplicate or invalid recipient addresses block execution before broadcast.
  6. The CSV must not include token, amount, bridge purchase, fulfillment batch, or fulfillment nonce fields.
  7. Coupon Broadcaster stops on the first failed row and downloads a CSV result file after execution.
address,label,email,subscriber_id,first_name,last_name,company,phone,source,signup_date,consent_email,consent_sms,notes
kaspatest:replace_with_coupon_receive_address,Todd,todd@example.com,SUB-001,Todd,Example,Example Company,555-0101,website-form,2026-05-06,yes,no,example note

Create KRC-20 trading wallet

Create a wallet. You must set a passphrase to encrypt your keyfile (saved locally). This passphrase is never sent to the server.

Passphrase cannot be blank. Leading and trailing spaces are ignored by this form; do not rely on spaces at the beginning or end. Use a unique passphrase and save it offline.
Compliance Wallets are broker-custody wallets. CN holds the protected custody signer; the local keyfile authorizes requests.

Change Passphrase

Re-encrypt the current keyfile with a new passphrase. This does not change the wallet address, holdings, mnemonic, or derivation settings.

Recover wallet

Recover an existing Standard Wallet on this server. You must provide either the encrypted keyfile or the recovery file, plus the passphrase and the mnemonic phrase. Compliance Wallet recovery is no longer supported because Compliance Wallets are broker-custody wallets.

Import KRC-20 wallet

Import a compatible standard wallet using a mnemonic phrase and passphrase. This diagnostic proof path supports Account 0 or Account 1, scans receive indexes 0 through 49, and tests both entered-passphrase and blank-passphrase derivation against the address you provide for the currently selected network.
